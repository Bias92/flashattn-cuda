# Grouped-query attention, RTX 4060 Ti, 2026-09-14

`cuda/attention_forward.cu` gained a `GQA` template parameter. Several query heads read one
key/value head, so K and V are addressed through a grouped index computed once per block:

    bh_kv = (bh / H_q) * H_kv + (bh % H_q) / (H_q / H_kv)

With equal head counts that branch compiles out. Register use of the eight non-GQA instances
is unchanged (82 / 82 / 85 / 88 for O-only and 82 / 94 / 85 / 88 for the +L variants), so the
earlier dense and causal numbers still describe the same machine code.

## Correctness

## What the two configurations together say

With 8 heads this kernel led the FlashAttention-2 backend on causal at both lengths. With 32
query heads it leads at N=2048 in both mask modes, and falls behind both backends at N=4096.
The small tile buys occupancy when there is not much work per launch and costs data reuse once
there is; 32 heads at N=4096 is enough work that the 128x128 tile wins. Neither configuration
makes this kernel generally faster, and cuDNN is ahead of the FlashAttention-2 backend in most
cells of both tables.

FLOPs counted as 4·N²·D·H, halved for causal.
