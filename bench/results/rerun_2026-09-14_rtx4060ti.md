# RTX 4060 Ti measurements, 2026-09-14

Re-measured after the kernel was restructured into helpers (52126b0) and its identifiers
renamed (4cd0831). Those two commits changed the source of the kernel the earlier numbers
were taken on, so both correctness and latency were taken again.

## Environment

- GPU: NVIDIA GeForce RTX 4060 Ti, 8188 MiB, driver 595.97 (WDDM, drives the display)
- Host: Windows 11, WSL2 Ubuntu 24.04.1, Python 3.12.3, torch 2.10.0+cu128, CUDA 12.8
- Build: torch.utils.cpp_extension.load, -O3 --use_fast_math -gencode=arch=compute_89,code=sm_89
- Source: cuda/attention_forward.cu @ 4cd0831
- Register use, WRITE_L=true FULL_TILES=true instance: REG 94, STACK 0, LOCAL 0, SHARED 18432
  (the pre-restructure build reported REG 95)

## Correctness

`python3 tests/test_attention_forward.py` on 4cd0831: 19/19 passed. Every reported O and L
difference matches the pre-restructure run digit for digit, so the restructure did not change
what the kernel computes.

## Latency

`python3 bench/compare_pytorch.py`, three separate runs. Each run is 10 paired reps with
alternating order. GPU was at 0-10% utilization before each run, with no Windows process above
1% on the GPU engine counters.

    run 1   N=1024  0.0672 / 0.0718 ms   gap -5.64%
            N=2048  0.2142 / 0.2141 ms   gap +0.11%
            N=4096  0.8387 / 0.8332 ms   gap +0.73%
    run 2   N=1024  0.0642 / 0.0611 ms   gap +2.98%
            N=2048  0.2137 / 0.2134 ms   gap +0.76%
            N=4096  0.8383 / 0.8302 ms   gap +1.20%
    run 3   N=1024  0.0624 / 0.0624 ms   gap +4.33%
            N=2048  0.2157 / 0.2139 ms   gap +1.11%
            N=4096  0.8378 / 0.8293 ms   gap +0.90%

Median of the three runs, custom / SDPA:

| N | custom ms | SDPA ms | gap | custom TFLOPS | SDPA TFLOPS |
|---:|---:|---:|---:|---:|---:|
| 1024 | 0.0642 | 0.0624 | +2.98% | 33.4 | 34.4 |
| 2048 | 0.2142 | 0.2139 | +0.76% | 40.1 | 40.2 |
| 4096 | 0.8383 | 0.8302 | +0.90% | 41.0 | 41.4 |

At N=1024 the per-rep gaps span -15% to +15%, so that row carries launch and dispatch noise
rather than kernel time. N=2048 and N=4096 are stable across all three runs.

Both sides are faster than in the 2026-09-06 record (custom 0.8544, SDPA 0.8413 at N=4096),
so part of the change is machine state rather than the restructure. The paired gap, which is
insensitive to that, narrowed from +1.37% to +0.90% at N=4096.

FLOPs counted as 4·N²·D·H. Peak for fp16 multiply with fp32 accumulate:
34 SM × 512 FLOP/clk × 3.12 GHz = 54.3 TFLOPS at max boost; sustained clock under load is lower.

## Memory

Not re-measured on 4cd0831. The 2026-09-06 numbers stand: peak allocation is decided by the
output and logsumexp tensors, which the restructure did not touch.
